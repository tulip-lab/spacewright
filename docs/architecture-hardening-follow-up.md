# SpaceWright 架构加固剩余工作：Codex 执行指令

请直接修改 SpaceWright，完成下面尚未完成的架构与可靠性修复，并用隔离测试验证。不要停留在评估或建议阶段，不要把上一轮已通过的测试当作剩余契约已经实现的证据。

## 工作边界

- 遵守当前仓库 `AGENTS.md`；先检查分支、Git 状态和现有代码，保留无关改动。
- 仅修改 SpaceWright，不修改 Mackup、个人配置、安装中的版本或系统设置。
- 不使用子代理。
- 按 Git Flow 在合适的现有 `feature/*` 分支继续；没有合适分支时，从最新 `develop` 创建 `feature/architecture-hardening-follow-up`。
- 保留公共 Fish 命令和必要的兼容路径，不一次性重写整个运行时。
- 本指令只授权实现和隔离测试，不授权提交、合并、推送、部署或真实桌面测试。
- 常规实现选择自行判断；只有无法从代码和上下文解决、且会实质改变结果的选择才询问用户。

## 测试安全边界：先验证，再运行

上一轮早期安装 smoke 曾因锁包装启动子进程、测试函数替身未继承而调用真实 yabai，包括窗口及 Space 操作请求。是否生效未确认。这是测试隔离缺陷，不是获准的真实测试，也不能作为功能验证证据。

当前 `work_smoke` 已使用隔离状态目录、真实可核验 lease 和外部命令阻断。但本次必须先审查所有要运行的测试入口，特别是安装、release、子进程以及复杂适配器测试，确认隔离仍成立。

- 每个子进程使用隔离的 HOME、配置、机器状态、缓存和日志目录；Fish 使用 `--no-config`。
- 测试中外部 `yabai`、`displayplacer`、`open`、`launchctl`、`osascript`、`killall` 默认阻断；需要行为的测试只能使用明确的假命令或 fixture。
- 不依赖仅在父 Fish 中定义的替身，不允许测试通过 PATH 或绝对路径落入真实桌面程序。
- 用遗漏一个函数替身的负例证明：子进程仍被阻断，不能修改真实桌面。
- 不移动真实窗口，不创建、销毁或切换真实 Space，不切换显示器，不激活应用，不重启服务；不得为验证或“回滚”上轮事故而擅自修改桌面。

## 实施顺序与验收

先安全边界与执行一致性，再应用恢复与预算，最后模块收口。每个实际缺陷先增加能证明错误行为的针对性测试，再修复。

### 1. 完成整模式 Sandbox、清理、排序及后处理的固定对象契约

目前整模式 Sandbox 收集和带执行锚点的 postprocessor 仍在 Fish 内计算部分动作。`ws_window` 会拒绝 immutable envelope 未列出的窗口，可能导致这些流程失败关闭，尚不能视为完整的规划/执行一致性。

- 将全局收尾需要操作的窗口、Space UUID、显示器及几何列入计划；所有权、cardinality、排除规则与后置验证使用同一策略。
- 后处理不得重新选窗或扩大对象范围；不要通过放松 `window-check`、绕过 lease 或忽略错误消除失败。
- 创建 Space 后记录实际 UUID；后续移动、标签、清理和排序按 UUID 重新解析索引。
- 创建、销毁、排序、应用恢复等非窗口副作用必须列入预览和执行日志。
- 清理、销毁前要求完整且足够新鲜的发现，重新验证占用与至少一个幸存 Space；发现失败立即停止。
- 计划外对象出现、对象消失、身份变化或相关前置条件失效时停止或明确重新规划，并记录原因。

验收：模式计划的 Sandbox/postprocessor/清理/排序对象与实际对象一致；不完整发现零破坏性操作；新窗口不会被执行器偷偷收集；UUID 重排仍操作正确 Space；再次执行收敛目标零变更。

### 2. 实现单工作区精确限定的局部与相反变体清理

当前单工作区 pinned 执行保留相反变体，避免调用 family-wide opposite-mode cleanup。这是保守过渡行为，尚未完成原请求中的局部收尾。

- 从同一有效配置解析目标工作区的相反变体标签，发现并记录其确切 Space UUID。
- 在计划中显式表示局部清理动作，仅限该工作区及这些相反变体；处理自定义标签、共享 runtime id、inactive workspace 和重复标签。
- 删除前重新核验 UUID、标签、显示器、完整发现和占用；有窗口或身份不符时保留并报告，不得从“未选到窗口”推断 Space 为空。
- `apply`、网页和交互式 `workspace` 对同一目标使用相同范围，不执行全局 Sandbox、全局清理、全局排序或整模式 finalize。

验收：目标、相反变体及另一个工作区同时存在时，只处理明确许可的局部对象；其他工作区和用户 Space 的状态不变；partial discovery、标签冲突和非空 Space 均阻止局部销毁。

### 3. 完成复杂应用与固定适配器的契约迁移

Office 多文档和 Dia 已有共享几何规则；应用重开、原生全屏恢复及 coding control、GTD chat/calendar 等固定适配器尚未完整迁移。当前 pinned 路径不能承诺与其全部历史行为等价。

- 保留复杂应用的显式 Fish 恢复适配器，逐个定义输入、输出、可能副作用、总期限、执行前置条件及验证标准。
- 简单工作区继续使用固定对象路径；再逐个覆盖 Office、Dia、Outlook/Preview、coding control 和 GTD chat/calendar，避免一锅重写。
- 适配器可能创造、重开或替换窗口时，将其作为明确准备阶段；恢复结束后重新发现、生成新的固定计划并记录与原计划的关系。
- 不允许已有计划中的窗口消失后自动选择替代窗口继续；身份变化必须有明确重新规划。
- 原生全屏、最小化、可见性、bundle ID、独立所有权和多窗口选择不能在 JS 与 Fish 中采用不同语义。
- 复杂布局中的 grid、region、absolute 等实际几何必须同时被规划、执行、验证与恢复理解；不允许缺少几何比较却宣告目标完成。
- 已选可选窗口发生操作失败仍应传播；只有明确的可选缺失/跳过才容错。

验收：用 fixtures 覆盖适配器恢复创建新 ID、旧 ID 重用、恢复失败、成功但未生效、超过期限、多个候选与部分窗口失败；预览、执行、验证和恢复记录始终可追溯到同一对象或显式新计划。

### 4. 统一整次执行的重试和服务恢复预算

共享期限与 pinned apply 的单次 reconciliation 已实现，但旧适配器仍有各自的确认/恢复循环。不能把“每层有界”视作“整次执行预算统一”。

- 区分只读确认轮询、命令重试、应用恢复、服务恢复、整次 reconciliation，统一挂在可核验 lease/run 上。
- 每次使用预算前读取并原子更新剩余额度；内部嵌套调用和多个子进程不能各自重置。
- 将剩余总时间传给所有恢复/查询/命令子步骤；到期或取消立即停止后续操作。
- 已取消或超时的执行不得进入 reconciliation、应用重开或服务重启。
- 不能仅靠环境变量授权预算复用；沿用 token、所有者进程身份和祖先检查。

验收：模拟多层调用和并发子步骤，证明全执行最多消耗配置的重试/恢复额度；时间预算不因子步骤重置；服务恢复在默认只读测试中永远不落入真实命令。

### 5. 完善中断、日志写入失败和恢复记录的耐久性

当前日志主要记录 issued/attempted 命令；突然杀死控制器时，缺少逐命令持久 acknowledgment，不能准确承诺所有操作已完成或已撤销。

- 在每次变更前持久化对象身份、目标 UUID、操作意图和恢复候选；命令完成后记录退出结果与可核验后置条件。
- 明确区分未尝试、已尝试但结果未知、已验证成功、失败、取消；恢复不得操作仅被选择但未操作的窗口。
- 子进程不响应 TERM 时在有界宽限后 KILL；确认所有相关进程组停止才释放 lease。保留未知活跃所有者的保守策略。
- 覆盖 controller crash、发现失败、执行失败、验证失败、journal 写入失败、状态文件不可写、取消和超时。
- 存储不可用时不能保证磁盘终态，必须在可用通道清晰报告状态与最后步骤；恢复存储后可以明确修复未终结记录，不得静默报成功。
- 恢复核验窗口 ID、app、PID/进程寿命与 bundle；每一步按 Space UUID 重新解析索引；最后重新发现验证位置、尺寸和归属。
- 恢复结果明确区分完成、部分、跳过、失败、取消、超时，列出不可恢复副作用，保留命令成功但实际无效的检测。

验收：故障注入在“写意图后”“命令后 acknowledgment 前”“验证前”等位置中断；重启后不会盲目重复破坏性动作或恢复未操作对象；日志写入失败不吞错、不留下仍运行的子进程。

### 6. 收口配置存储与自动化监控模块

- 检查 `server.mjs` 中剩余机器绑定、setup 激活、备份恢复、历史恢复和拓扑触发写入，统一使用同一保存/generation 契约。
- 对并发保存、读写交错、外部源文件变化和多文件保存中断做针对性测试；执行始终读取一致配置和机器状态。
- v3 缓存继续校验编译器、源配置、硬件、物理拓扑、绑定和生成运行时；未知/未确认拓扑在变更前阻止执行。
- 将监控启动、停止、拓扑 debounce、事件触发和任务生命周期移到职责清晰的模块；避免为了拆文件增加无用途的抽象。
- 清理未使用的导入/重复 helper，减少 Fish 全局执行上下文；区分机器持久状态、run 状态与短缓存。
- 缓存 TTL、runtime generation、app/PID/进程寿命身份检查不能在不同消费者中退化为“文件存在即有效”。

验收：不同入口保存/恢复后读取一致 generation；进程退出时监控停止，任务落入终态；并发激活/保存不能执行混合版本；旧缓存不会屏蔽重用 ID 的新窗口。

## 最终验证与交付

1. 运行每个修复的针对性测试及受影响回归。
2. 对所有修改/新增 Fish 文件逐个运行 `fish -n`，对修改的 JS 做语法检查。
3. 验证配置/schema、编译、保存往返、硬件拓扑与绑定变化、保存中断和并发写入。
4. 在外部命令阻断与隔离目录中验证所有公共入口 dry-run 零变更。
5. 验证目标收敛后二次执行零变更，以及单工作区之外状态不变。
6. 在源文件停止修改后运行完整 `fish --no-config scripts/check.fish`，避免改动源码导致两个 release archive 的可复现性比较失效。
7. 运行 `git diff --check`，检查最终 Git 状态，不擅自提交。
8. 更新架构、状态协调、模式切换、恢复文档，删除已经真正解决的剩余限制描述。
9. 最终逐项报告本指令六组工作的完成状态、关键修改、实际运行检查及尚未验证的真实 macOS 行为。
10. 未完成项必须说明原因、剩余风险和具体下一步；不得用测试通过替代尚未实现的契约，不得承诺完整桌面回滚。
